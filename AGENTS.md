# Repository Guidelines

## Project Structure & Module Organization
- `src/` is the Python package; `src/main.py` orchestrates runs, `src/scraper.py` handles OLX GraphQL fetching, `src/charts.py` builds Plotly dashboards, and `src/models.py` contains dataclasses.
- `products.yaml` defines tracked items; each `slug` maps to outputs like `data/<slug>.csv` and `images/<slug>_dashboard.png`.
- `data/`, `images/`, and `README.md` are generated by the pipeline; update them by running the app rather than editing by hand.

## Build, Test, and Development Commands
- `uv sync` installs dependencies from `pyproject.toml` and `uv.lock` (or `pip install -e .` if you do not use uv).
- `python -m src.main` runs the full pipeline, updates CSVs, regenerates dashboards, and rewrites `README.md`.
- `ami` runs the same entry point after the package is installed.

## Coding Style & Naming Conventions
- Use Python 3.11+, 4-space indentation, and type hints; keep models as dataclasses like existing code in `src/models.py`.
- Prefer snake_case for functions/variables and CapWords for classes.
- Keep product slugs in kebab-case and align filenames with slugs (`data/<slug>.csv`, `images/<slug>_dashboard.png`).
- No formatter or linter is configured; follow existing import grouping and line length patterns.

## Testing Guidelines
- There is no automated test suite yet.
- Validate changes by running the pipeline and checking for a new CSV row plus updated PNGs and `README.md`.

## Commit & Pull Request Guidelines
- Commit messages: use `Update: YYYY-MM-DD` for data refresh commits (often prefixed with a chart emoji in history); use imperative verbs like "Add", "Fix", or "Simplify" for code changes.
- PRs should include a short summary, note any scraping or rate-limit changes, and include regenerated `data/`, `images/`, and `README.md` when relevant.
- If you change `products.yaml`, call out new slugs and confirm dashboards were generated.
